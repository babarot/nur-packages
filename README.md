# nur-packages

Nix packages for [babarot](https://github.com/babarot)'s tools.

[![Check](https://github.com/babarot/nur-packages/actions/workflows/check.yaml/badge.svg)](https://github.com/babarot/nur-packages/actions/workflows/check.yaml)

## Usage

```sh
nix run github:babarot/nur-packages#naminator
```

As a flake input:

```nix
inputs.babarot.url = "github:babarot/nur-packages";
# ...
home.packages = [ inputs.babarot.packages.${pkgs.stdenv.hostPlatform.system}.naminator ];
```

## Packages

Every package installs the prebuilt binary of a release. Nothing here is built from source. Each `pkgs/<name>/default.nix` is generated when the tool is released and pushed here by a bot, so do not edit it by hand: change the tool's release configuration instead.

| Package | Command | Generated by | Binary |
|---------|---------|--------------|--------|
| [c-c-statusline](https://github.com/babarot/c-c-statusline) | `c-c-statusline` | The tool's release workflow | `deno compile`, dynamically linked |
| [changed-objects](https://github.com/babarot/changed-objects) | `changed-objects` | GoReleaser | Go, statically linked |
| [claude-recall](https://github.com/babarot/claude-recall) | `recall` | GoReleaser | Go, statically linked |
| [enter](https://github.com/babarot/enter) | `enter` | GoReleaser | Go, statically linked |
| [gh-infra](https://github.com/babarot/gh-infra) | `gh-infra` | GoReleaser | Go, statically linked |
| [gist](https://github.com/babarot/gist) | `gist` | GoReleaser | Go, statically linked |
| [naminator](https://github.com/babarot/naminator) | `naminator` | GoReleaser | Go, statically linked |
| [syno](https://github.com/babarot/syno) | `syno` | GoReleaser | Go, statically linked |

claude-recall also installs its Claude Code plugin under `share/claude-plugin/claude-recall`.

### GoReleaser

The tool's `.goreleaser.yaml` has a [`nix` section](https://goreleaser.com/customization/nix/) pointing at this repository. On each release GoReleaser writes the derivation from the release archives and commits it as goreleaserbot. The derivation unpacks the archive and copies the binary; Nix's usual fixup runs on it, which changes nothing in a statically linked Go binary.

### The tool's release workflow

c-c-statusline is a Deno program, and `deno compile` keeps the program at the end of the executable. Nix's fixup patches the interpreter and rpath of a dynamically linked Linux binary and appends the new paths to the file, which breaks it. GoReleaser's derivation cannot turn fixup off, so the release workflow of c-c-statusline writes its own derivation with `dontFixup = true` (`.github/scripts/nix-derivation.sh` there) and commits it as github-actions[bot].

The binary expects the system's dynamic loader (`/lib/ld-linux-*.so`), so on NixOS it does not run as it is.

## Check

The [Check](.github/workflows/check.yaml) workflow builds every package and runs it with `--version` on each push to main, including the bots' pushes, and on pull requests. It runs on x86_64-linux, aarch64-linux and aarch64-darwin; x86_64-darwin has no hosted runner left. A package that fails to build or to run fails the check. Output that does not mention the packaged version is a warning only.

Run it locally for the current system with:

```sh
.github/scripts/check-packages.sh
```

## Adding a tool

- A Go tool: add a `nix` section to its `.goreleaser.yaml`. See [babarot/naminator](https://github.com/babarot/naminator) for an example. GoReleaser needs a token that can push here, and `nix-hash` on the release runner.
- Anything GoReleaser cannot package: generate the derivation in the tool's release workflow, as [babarot/c-c-statusline](https://github.com/babarot/c-c-statusline) does.

Any directory under `pkgs/` is picked up by `default.nix` and the flake, so nothing else needs to change here.

## Removing a tool

Delete `pkgs/<name>`, and remove the `nix` section (or the workflow step) from the tool's release configuration. Otherwise its next release adds the package back.
